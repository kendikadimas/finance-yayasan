API Integrasi Keuangan

Modul Finance & Accounting dalam Sistem Informasi Terintegrasi Yayasan menyediakan lima endpoint baca-saja di bawah /api/v1/* untuk paket lain — Parent App, PPDB/Admission, Boarding Management, Teacher/Employee App, Procurement, dan Data Integration & Analytics / Executive Dashboard — menarik data yang sudah dicatat bendahara. Sistem ini tidak menerima data masuk lewat API ini.

EndpointAbilityDipakai oleh (contoh)
GET /pembayaran-spp read:pembayaran-spp Parent App — riwayat bayar SPP
GET /tagihan-siswa read:tagihan-siswa Parent App, PPDB (uang pangkal), Boarding (boarding fee)
GET /hutang-vendor read:hutang-vendor Procurement — status pembayaran invoice vendor
GET /penggajian read:penggajian Teacher/Employee App — slip gaji
GET /laporan/ringkasan read:laporan-ringkasan Data Integration & Analytics, Executive Dashboard

Klien & ability

Sistem eksternal tidak login sebagai pengguna manusia. Setiap sistem didaftarkan sebagai satu Klien API oleh admin di Keuangan > Klien API.

  1. Daftarkan klien. Admin memberi nama (mis. “PPDB” atau “Parent App”) dan mencentang ability mana saja yang boleh diakses klien itu — hanya yang dibutuhkan, tidak semua.
  2. Simpan tokennya. Token Sanctum terbit terkunci ke ability yang dicentang, dan ditampilkan satu kali saja — salin segera, token tidak bisa dilihat ulang.
  3. Ubah ability bila perlu. Mengubah ability klien tidak otomatis mengubah token yang sudah beredar (ability terkunci saat token dibuat) — klik “Terbitkan Ulang” agar token baru memakai ability terbaru; token lama langsung tidak berlaku.
  4. Nonaktifkan kapan saja. Menonaktifkan klien menolak semua request-nya (403) tanpa perlu mencabut tokennya.
Setiap endpoint mengecek ability token-nya sendiri selain dicek middleware (token valid + klien aktif) — token dengan ability yang salah ditolak walau valid dan klien-nya aktif.

Pola umum tiap endpoint

HalKetentuan
AutentikasiHeader Authorization: Bearer <token>
FormatJSON, dipaginasi (data, links, meta), parameter per_page 1–100 (default 25) kecuali disebutkan lain
Rate limit60 request/menit per klien

Error umum

  • 401 Token tidak ada atau tidak valid.
  • 403 Token tidak punya ability yang sesuai, atau klien dinonaktifkan.
  • 422 Parameter query tidak valid.

Pembayaran SPP read:pembayaran-spp

Riwayat pembayaran SPP yang sudah tercatat. Dipakai oleh Parent App untuk menampilkan riwayat bayar ke orang tua.

GET/api/v1/pembayaran-spp

Parameter query (semua opsional)

ParameterTipeKeterangan
kode_unitstringFilter berdasarkan kode unit sekolah
kode_siswastringFilter berdasarkan kode siswa
periodestringFilter berdasarkan periode tagihan
tanggal_daridateTanggal pembayaran mulai (Y-m-d)
tanggal_sampaidateTanggal pembayaran sampai (Y-m-d)
per_pageinteger1–100, default 25

Contoh request

bash
curl -H "Authorization: Bearer <token>" \
  "https://finance.yayasan.test/api/v1/pembayaran-spp?kode_unit=U1&periode=2026-10"

Penggajian read:penggajian

Ringkasan Laporan read:laporan-ringkasan

Ringkasan pemasukan, pengeluaran, dan saldo kas/bank per unit untuk satu periode. Dipakai oleh modul Data Integration & Analytics dan Executive Dashboard tingkat yayasan untuk KPI “Keuangan”.

GET/api/v1/laporan/ringkasan

Tidak dipaginasi — jumlah unit yayasan kecil, seluruh unit dikembalikan sekaligus.

Parameter query (semua opsional)

ParameterTipeKeterangan
daridateAwal periode (Y-m-d). Default: awal tahun berjalan.
sampaidateAkhir periode (Y-m-d). Default: hari ini.

Contoh request

bash
curl -H "Authorization: Bearer <token>" \
  "https://finance.yayasan.test/api/v1/laporan/ringkasan?dari=2026-01-01&sampai=2026-12-31"

Contoh response

json
{
  "data": [
    {
      "unit_id": 1,
      "kode_unit": "U1",
      "unit": "Unit Satu",
      "pemasukan": 500000000,
      "pengeluaran": 420000000,
      "saldo_bersih": 80000000,
      "saldo_kas_bank": 95000000
    }
  ],
  "meta": {
    "total_pemasukan": 500000000,
    "total_pengeluaran": 420000000,
    "total_saldo_kas_bank": 95000000,
    "periode": { "dari": "2026-01-01", "sampai": "2026-12-31" }
  }
}

Di luar scope

Ini murni jalur baca. Sistem ini tidak menerima data masuk lewat API — integrasi payment gateway pihak ketiga hanya opsi konfigurasi, bukan kewajiban.

Tidak ada jalur tulis

Tidak ada endpoint untuk sistem lain membuat tagihan, menandai pembayaran, atau memproses uang lewat API ini.

Belum ada endpoint create

Kalau PPDB/Boarding perlu membuat tagihan uang pangkal atau boarding fee lewat API (bukan cuma baca status), itu endpoint tambahan yang belum dibangun dan perlu keputusan terpisah.
